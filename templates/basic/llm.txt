# Basic starter installation instructions for an AI assistant

Set up the Vite/React web app, PostgreSQL, Better Auth, and the API. Follow the user's chosen project name and directory. Do not run generators in the source template repository; work inside the newly created project. Ask before overwriting an existing project, environment file, database, or migration. Never print or commit secrets.

1. Check prerequisites: Node.js 24+, pnpm 12, and Docker Compose with a running Docker engine. If the project does not yet exist, create it with:

   pnpm dlx create-turbo@latest <project-name> --example https://github.com/madflow/projectx/tree/main/templates/basic --package-manager pnpm

   `--package-manager pnpm` avoids an interactive selection prompt in non-interactive shells. Change into the new project directory and run `pnpm pkg set name=<project-name>` to update the root `package.json` name: `create-turbo` leaves it as `my-turborepo`. Use the same name the user chose for the new directory. `create-turbo` copies the example but does not run its generators. If a project was already created, use that project instead of creating another one; check its root package name and rename it if needed.

2. Install the starter dependencies if create-turbo did not already do so, then add the optional database and auth/API workspaces in order:

   pnpm install
   pnpm turbo gen database
   pnpm turbo gen auth
   pnpm install

   The database generator creates `packages/db`, `compose.yaml`, and `.env.example`. The auth generator adds `packages/auth`, `packages/api`, `apps/api`, the login UI, and the auth variables in `.env.example`. Neither generator needs a yes/no confirmation. Do not rerun them over workspaces that already exist. Do not run `pnpm check` yet: auth imports `@repo/db/schema/auth`, which does not exist until step 4 generates it.

3. Set up the local environment only after both generators:

   pnpm env:copy-example

   This command does not overwrite an existing `.env`. Ensure it contains `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, and `WEB_ORIGIN`. For the default local setup, `BETTER_AUTH_URL` is `http://localhost:3000` and `WEB_ORIGIN` is `http://localhost:5173`. Set `BETTER_AUTH_SECRET` to a cryptographically random value of at least 32 characters, without showing it in logs or committing `.env`. If `.env` already exists, preserve it and add missing values with the user's approval. If you cannot safely populate it, ask the user to do so before starting the API.

4. Generate the Drizzle auth schema from the Better Auth configuration, then create the SQL migration:

   pnpm auth:generate-schema
   pnpm db:generate

   `packages/auth/src/schema.config.ts` is the source of truth for auth options and schema-affecting plugins. Better Auth 1.7.6 generates `packages/db/src/schema/auth.ts` with plural table names, UUID IDs, PostgreSQL `gen_random_uuid()` defaults, and relations for joins. Generate this schema before running `pnpm check`; it needs the root `.env` from step 3, but not a running database. `pnpm db:generate` creates SQL migrations under `packages/db/drizzle/` from all `packages/db/src/schema/*.ts` files. Review generated migrations before applying them, especially if this is not a fresh database. Do not hand-edit the generated auth schema; regeneration replaces it.

5. Start PostgreSQL, wait for it to be healthy, and apply migrations:

   docker compose up -d
   pnpm db:migrate

   The database URL must point to the running PostgreSQL instance. Do not delete volumes or run `docker compose down -v` against data that might need to be kept. Better Auth's `migrate` command is not used with this Drizzle adapter; `pnpm db:migrate` applies the SQL generated by Drizzle.

6. Run `pnpm check`, then `pnpm dev`. Open `http://localhost:5173` for the web app. The API runs at `http://localhost:3000`; check `/api/v1/health` and `/api/v1/docs`. Report what passed, what remains unverified, and any prerequisite or permission that blocked setup.

When auth plugins or other auth schema options change later, rerun `pnpm auth:generate-schema`, `pnpm db:generate`, and `pnpm db:migrate` in that order. For other app tables, add separate files under `packages/db/src/schema/`. See `README.md` for development details and PostgreSQL upgrade precautions.
